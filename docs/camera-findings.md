# 自由相机（灵魂出窍）探测记录

目标：做出 Akebi 那种「人物定住 + 镜头自由飞」的效果。

## 结论摘要

PC 端（7.1 国际服，Unity 静态链接）的相机遇到了三道坎，逐条记录，避免以后重复踩。

## 探测一：按坐标找（失败）

思路：相机在角色附近，扫堆里等于/接近角色坐标的 float 三元组。

结果：能找到大量副本，但转视角后它们的值变成方向向量（±1 那种），说明这些是**每帧复用的临时缓冲**。

## 探测二：加「距离恒定」过滤（成功定位到相机位置，但只是副本）

思路：相机绕角色转、到角色距离恒定。可用约束：

- 转视角后位置变化 > 0.3 m
- 排除三分量都在 ±1.5 内的方向向量
- 到角色距离变化 < 2 m
- 距离落在 1.5~15 m

结果：**成功**。数据非常干净：

```
2749.32 196.27 -1713.49  ->  2752.70 196.28 -1720.80     dist 6.2 -> 6.2
```

- 距离恒定 6.2 m（默认相机距离）
- 转视角时绕角色划弧
- 高度比角色高 1.65 m
- 一次能扫到 252 个副本（渲染管线每帧复制）

## 探测三：转储结构看布局（确认是渲染副本）

对相机候选 ±256 字节做浮点 + 指针双视图转储，结果：

```
位置: 2745.891  196.825  -1724.806
前面: 1.000 1.000 1.000 1.000          ← 颜色/UV
前面: 8.000 128.000 4096.000           ← 缓冲尺寸类参数
后面: 0.000 ... nan nan                ← 顶点数据残留
```

特征符合**顶点缓冲 / 粒子数据**，不是相机控制器。

**结论：相机位置每帧由控制器算出后拷贝到渲染临时区，写这些地址无效。**

## 还没试的两条路

### A. 扫 yaw / pitch 对

相机控制器里必然存视角角度：

- yaw 范围 -180~180
- pitch 范围 -89~89（原神默认下视约 -30）

做法：扫全堆里的相邻 float 对，转视角时两者同时变化的就是候选；定位到控制器后再读它附近的
`6.2`（距离）和目标指针。

优点：不依赖"位置"，控制器是长期存在的。缺点：角度类浮点很多，需要两三次采样交叉过滤。

### B. 指针扫描

1. 找到角色位置那一块稳定结构（探测三里 dump #2 就是角色对象：能看到坐标 + 血量 911.791 两次）
2. 全堆搜"值等于这个地址"的 qword（指针扫描）
3. 逐个转储持有者，找含 `~6.2` 距离和两个角度的结构

优点：目标明确。缺点：要人工看结构布局。

## 参考：Akebi 的做法

Akebi 是安卓 IL2CPP，走的是「版本偏移表 + hook 相机组件更新函数」：先按偏移拿到
`CameraManager`，再在它的更新之后覆盖 transform，同时关掉输入到相机的绑定、绕过碰撞。
它靠的是**每个版本维护一份偏移**，不是内存扫描。PC 端没有公开的偏移表，只能自己找。

## 探测四（方案 B）：从相机位置做指针扫描 —— 0 持有者

思路：相机控制器为了跟随角色/计算位置，必然持有指向相机位置结构的指针。
做法：锁定相机位置字段 → 全堆搜"值等于该地址（±0x80）"的 qword → 转储持有者。

过程与坑：

1. 第一次锚定"角色对象"（判据：坐标一致 + 附近血量出现两次）→ 找到的其实是**线程栈上的临时拷贝**，
   31 个持有者全挤在 4 KB 内，是栈帧而不是堆对象
2. 改成锚定**相机位置**（距离 3~12 米、非方向向量）→ 持有者只剩 4~6 个
3. 转储时发现持有者在 `Astrolabe.dll` 内 —— **是我们自己的 `g_camCands[]` 数组自我命中**
   （数组里存的就是相机地址，扫描在找"值等于该地址"的 8 字节）。上一轮误判为"静态相机数组"，
   实际是候选缓冲区的 `{v[0], v[1], v[2], dist}` 布局
4. 加上"排除自身模块"后重新扫描：**0 个持有者**

结论：**进程里没有任何长期结构持有相机位置字段的指针**。相机位置由某个函数现场算出、写进临时/渲染缓冲，
用完就丢，因此指针扫描这条路走不通。

## 还没试的最后一条：硬件断点

思路：在相机位置字段上设**写断点**（调试寄存器 DR0/DR7，RW=01），由 VEH 捕获异常，
异常的 RIP 就是"写相机位置的那条指令"，顺着栈回溯能定位相机更新函数，再 hook 它。

难点：

- DR 寄存器是**线程私有**的，要设到渲染线程上必须 `SetThreadContext` 逐线程操作
- 该地址每帧都被写，断点会高频触发，必须先只在少数几次命中里采集信息
- 一旦设置错误，客户端会崩（有 PE 保护的情况下风险更高）

工作量：还需要 2~3 轮探测 + 一次 hook 实现，且不可回滚的部分要靠 VEH 兜底。
